# Historical releases

`manifest.json` records the archived assets, their original download URLs, byte lengths, SHA-256 hashes, and the application metadata extracted from each ZIP. The files are preserved as GitHub release assets, not stored in the source repository or the Pages artifact. The `v2.41` release had no attached assets, so its source ZIP was generated from the upstream Git tag and is identified by `generated_from_tag`.

For an application ZIP, `plist_min` comes from its Info.plist, `architectures` and per-architecture `min_os` come from the Mach-O executable, and `icon_sha256` identifies the ICNS resource named by the application. A null minimum is unknown; an architecture only establishes the platforms for which code is present. For source-only releases, matching bundled application metadata is preferred. Otherwise, the application target’s explicit Release settings are used where interpretable; `project-settings-audit.json` records the project and settings checked. Default architectures and ambiguous build configurations remain unknown. For source-only versions 3.13, 3.19–3.20, and 3.27–3.33, the catalog uses the 128-pixel PNG in the root Icons.iconset: the application target includes that icon set in its resources, and Info.plist names Icons as the app icon. The manifest records the exact source paths.

The version 5.49 notes state that versions 5.00–5.48 crashed on Mojave; the catalog notes that exception independently of their minimum version. PowerPC and 32-bit Intel upper limits describe the last macOS versions capable of running those architectures, not a guarantee that every archived app runs on every earlier system.

`release-dates.json` records explicit release dates, public mailing-list announcement dates, and dates bounded by contemporary distribution records or the version sequence. At the maintainer’s direction, a public release announcement supplies day precision when no explicit release date is already known. The archive’s displayed posting date is retained; an announcement sent later does not replace an existing explicit release date. Sources, the evidence type (`basis`), and qualifications are recorded with each added entry. Revisions of the same version, development snapshots, and operating-system-specific builds are distinguished where the evidence permits.

A `date` can be `YYYY-MM-DD`, `YYYY-MM`, or `YYYY`. An optional `end_date` of the same precision represents a bounded interval. The generated pages display only the supported precision; they do not invent a first day of the month or label dates as estimates. The 17 versions marked unreleased retain their status labels; their displayed dates describe development snapshots, not public launches. `year-inferences.json` preserves the earlier year-only classification evidence. A few source-only versions are dated to the supported period of their archived development build, as explained in their records. Version 5.58 here is the Golden Gate variant, not the separate Tahoe build distributed with MacTeX 2026.

At the maintainer’s direction on November 10, 2026, an archived application `project.pbxproj` modification date supplies day precision where the date previously lacked it, provided it fits the existing date interval and surrounding versions in the same major series. This includes older `.xcode` and `.pbproj` containers. These are catalog-date proxies, not independently verified public release days. `project-date-evidence.json` records all 57 candidates, their archive hashes and paths, previous date evidence, chronological bounds, and acceptance or rejection reasons. 47 candidates were accepted; nine early archives carry 2016 project timestamps, and version 2.16 carries a 2009 timestamp inconsistent with its 2008 sequence, so those ten required a second check. The website displays dates without per-entry evidence notes, as requested.

For those ten exceptions, `info-plist-date-evidence.json` records the metadata-date fallback. Eight early versions retain contemporary timestamps in the source’s `English.lproj/CustomInfo.plist`, the localized application metadata referenced by Project Builder, even though the built app’s `Info.plist` was repackaged in 2016. Their dates were adopted as proxies after checking the version sequence. Version 1.0d5-Dirk’s December 31, 2000 timestamp is later than 1.0d6 (December 25, 2000); version 2.16’s `Resources/Info.plist` timestamp is December 8, 2007, outside its previously established 2008 interval. These two retain year precision. Together the project and metadata fallbacks supply 55 dates; existing day-precision records are unchanged.

The GitHub Release `published_at` and source commit dates often reflect later archival work and are not treated as release dates. ZIP entry timestamps are used only with independent chronological or public-availability evidence, not automatically as a release day. Some archives were repackaged in 2016, and some binaries were rebuilt after their first release. `date-conflicts.json` records earlier conflicts. For version 3.65, the maintainer selected July 13, 2016, the date used in later snapshots. For dated archive tags such as `1.00-2001-03-19`, the catalog shows the tag date at the maintainer’s direction; whether it is the actual public release date is not independently confirmed. Koch describes 1.0 as dated March 24, 2001, but also says it was put online a few days before that date; the catalog shows March 24 as the version date.

`Scripts/generate-historical-catalog.py` generates both language versions from these records. It does not upload, alter, or delete release assets.

Version 3.12’s source ZIP includes a TeXShop.app with matching version. Its Info.plist sets `CFBundleIconFile` to `Icons`, which identifies `TeXShop.app/Contents/Resources/Icons.icns`; document types use distinct icon settings. This is the icon shown in the catalog.

The icon-history illustration for 3.14–3.38 uses the icon from the 3.14 application. The 3.38 application uses a different ICNS encoding of the same visual design; individual releases are displayed using their own extracted icons.

`release-status.json` records the status of beta, development, unreleased and experimental versions and the evidence used for the labels. A final release is not labeled experimental merely because an earlier experimental build shared its version number; 2.15 was eventually made official.

`changelog-links.json` maps release tags to relevant archived change notes; dated 1.00 snapshots and letter-suffixed variants may link to their shared base-version notes. When the old change log lacks an individual entry for the earliest development builds, the links use Koch’s historical account instead.

`first-release.json` records version 1.0d1’s original 2000 release date and separately identifies the app and source as the 2024 recompilation, with compatibility and hashes checked from the preserved archives. These files are not the original 2000 distribution.

`icon-transition-notes.json` records the historical sources behind the short explanations of icon changes. The date associated with the earliest triangular-icon snapshot is inferred from its archive tag, not independently established as the first public appearance.

`cpu-transition-notes.json` records the change-log evidence for Intel, 64-bit and Apple Silicon milestones. An earlier unreleased 2.32 64-bit build is distinguished from the 3.00 official transition.

`requirements-inferences.json` documents estimated CPU/OS values and their bounding evidence; inferred values are recorded here rather than labeled in the catalog. The 2.32 source archive contains a matching 64-bit x86_64 application under `texshop2.32-64/build/Release/TeXShop.app`; adjacent official 2.31 and 2.33 applications are 32-bit PowerPC/Intel, but those architectures are not claimed for the distinct 2.32 source archive. Some early minimum OS versions remain unknown where historical requirements conflict or lack bounding evidence.
