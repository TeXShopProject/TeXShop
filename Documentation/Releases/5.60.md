# TeXShop 5.60

<!-- release-status: draft -->

TeXShop 5.60 fixes typesetting cancellation and improves LaTeX-aware spell checking, external file monitoring, editing long documents, and Settings.

## Typesetting and stability

- Run Experiment jobs in a separate console with independent input, cancellation and cleanup, so they do not interfere with normal typesetting. Closing or replacing an Experiment cancels only its own job.
- **Critical fix:** Fix a problem where Stop reported that typesetting had been aborted but left TeX running. Starting another typesetting job now also stops the previous job and its child processes.
- Handle failures to launch typesetting tools and missing command-search paths more reliably, and avoid an indefinite wait when stopping helper processes.
- Show a sheet when a specified TeX root file cannot be found.
- Fix errors involving empty documents, isolated quotation marks, and save-completion handling.
- Improve the handling of console output and log files that contain mixed encodings or broken characters. Read affected output line by line, trying UTF-8 and then the document’s encoding, with Latin 9 as a last resort. Keep unreadable data from spoiling other lines, and rejoin UTF-8 characters split by TeX’s line wrapping.

## LaTeX-aware spell checking

- Add LaTeX-aware spell checking, based on suggestions from Ralph Martin. It checks prose while skipping TeX commands, comments, mathematics, and arguments used for references and similar purposes. The feature is enabled by default and can be turned off under Settings → Spell Checking.
- Recognize supported macro definitions and language-switching commands when identifying text to check. The spelling panel can check passages in the specified language.
- Add editable spelling-exclusion rules, a replacement field and Change All for words in the checked text, and a way to forget learned words found in the current document. A Change All operation can be undone in one step.
- Fill the replacement field for Change All with the suggestion selected in the spelling panel, by clicking it or with the arrow keys. When there is only one suggestion, it is filled in as soon as the word is shown. The text changes only when Change All is used.
- Improve Find Next, scrolling to misspelled words, and spell-checking performance in long documents and split editors.

## External file changes and PDF preview

- Use the recorded source-click position and the clicked split editor for SyncTeX, including clicks at the start of a line and context-menu actions. Match valid filesystem aliases to SyncTeX inputs, prefer an exact recorded path, and reject paths that cannot be resolved.
- Preserve the page-relative position in both PDF panes after reloading, including content insets on macOS Tahoe. Preserve it across single-page and two-page navigation on macOS 27 when native PDFKit moves the viewport; skip the workaround when PDFKit already keeps the position. Up and Down arrows scroll within an enlarged page at a consistent on-screen step and stop at its edge.
- Keep PDF link previews within page and viewport bounds, with surrounding text and the appropriate column visible even for destinations near an edge.
- Pin an internal-link preview with Option, then move the pointer freely while explaining its contents; press Escape to dismiss it. Suggested by Uwe Schmock (#10).
- Size internal-link previews to the text column of the target page, so whole lines appear at the usual scale; in two-column documents only the target column is shown. A preview shrinks only when the window is too narrow, and never below half size. Suggested by Uwe Schmock (#12).
- Preserve the preview position when a window is closed and reopened during typesetting, including the combined source-and-preview window.
- Make source-file monitoring continue after automatic reloads and file replacement by external editors, including atomic saves. Preserve unsaved edits and the undo history for TeXShop’s own saves. This includes the contribution from ddd3h in PR #1.
- When Automatic Preview Update is enabled, detect PDFs changed by other applications and reload the preview while preserving the page position and zoom. Avoid replacing unsaved PDF annotations, and retry when an external writer temporarily leaves an incomplete PDF.
- Move file-change checks off the main thread to keep the interface responsive.
- Fix a PDFKit crash during preview reloads, including changes in page count, by correcting how PDF documents are shared with the second preview pane.
- Correct Space and Shift-Space scrolling when a PDF page is larger than the preview window.
- Add Page Layout and Two-Page Arrangement menus to the preview toolbar. Page Layout changes the page layout of the current document. Two-Page Arrangement changes the page direction and whether the first page is shown alone as a cover; Restore Document Settings returns these two to the document’s settings. The changes last until the document is closed. The page being viewed and the zoom are kept when the layout or arrangement changes.
- Add a check box under Settings → Preview, formerly a hidden setting, to show the first page alone as a cover in two-page layouts. Use the page direction recorded in the PDF unless a magic comment specifies the direction. These settings apply to documents opened afterward, and magic comments take precedence over them.

## Editing and keyboard navigation

- Settings now arranges controls in vertical groups with wrapping labels and indented dependent options. Theme colors are organized into eight named groups. Creating a theme asks for its name in a sheet; replacing an existing theme asks for confirmation and shows the theme name. The Keyboard list uses the remaining height.
- Edit menu shortcuts in Settings → Keyboard. Search by Function finds command names; Search by Key records a key to show matching menu commands and macros, including inactive assignments. Show in Macro Editor selects the matching macro. A new shortcut is recorded by pressing it, shortcuts already in use are reported, and one or all shortcuts can be restored. Shortcuts set in KeyEquivalents.plist remain the defaults. For the same key and modifiers, menu commands take precedence over macros; macros can use keys freed by customization. Confirm before assigning a macro’s key to a menu command. The Macro Editor marks inactive shortcuts, identifies the conflicting command and key, and asks about new or changed conflicts when saving. The bundled New array macro now uses Control-Shift-Command-A.
- Improve opening, scrolling, and editing long source documents by laying out text where needed and reducing repeated paragraph-layout work. Limit matching-brace searches on cursor movement.
- Preserve explicit left alignment in right-to-left paragraphs.
- Use Command-0 to show the current document’s console. Press it again in the console to return to the source or PDF window that opened it; if there is no originating window, return to the source. This follows the existing Command-1 behavior.
- Keep the Tags menu correctly localized when reopening a document in the combined source-and-preview window.

## Opening and saving documents

- Detect the encoding of a file that has no encoding magic comment when it is opened. Unicode files with or without a byte order mark, Japanese, Chinese and Korean files, and files in one-byte encodings of the user’s languages are recognized, with the encoding declared to inputenc as a hint. A hidden setting turns the detection off.
- Keep the byte order mark of UTF-8 files and the byte order of UTF-16 files when saving, and read encoding magic comments in UTF-16 files.
- Read GB 2312 files correctly, and stop a file that could not be read in its specified encoding from being damaged when it is saved.
- Always write TeX’s backslash and tilde as the bytes 0x5C and 0x7E in Japanese encodings. A typed backslash or tilde no longer becomes a full-width backslash or wave dash, or the byte 0x80, in Mac Japanese and Shift JIS X0213 files, and a yen sign typed for a backslash no longer becomes “?” in Windows Shift JIS, EUC-JP and ISO-2022-JP files.
- Use UTF-8 rather than Latin 9, with a message, when an encoding name is not recognized, and write project files in UTF-8.
- When an opened file has Windows (CRLF), classic Mac (CR) or mixed line endings, tell the user that they have been changed to LF. The notice can be turned off for each file.
- Fix the encoding menu in the Save dialog, which did not change the encoding of the saved file. The menu can now be shown from Settings → Documents and Saving. When the source has an encoding magic comment naming a known encoding, the menu shows that encoding and cannot be changed, unless the file could not be read in that encoding.
- Add settings under Settings → Documents and Saving to turn autosave and Versions on or off and, while autosave is off, to keep the previous file as “name~” when saving.

## App and Dock icons

- Introduce a white-frame app icon inspired by the classic circular icon, with optically centered TeX lettering and a rounded-square shape for current macOS versions.
- Add five Dock icon choices under Settings → Appearance, including historical designs. The selected icon retains its original shape while TeXShop is running. After quitting, the Dock returns to the standard app icon.

## Settings and themes

- When the default encoding changes while source windows are open, show the existing encoding warning below the setting instead of in a sheet.

- Apply the selected theme’s background, text, insertion-point colors and window opacity to Experiment source, preview and console windows where those controls are present. Experiment previews share the normal preview’s System, Light and Dark page appearance choices.
- Add Search Settings with an item-level result list showing each setting and its category. Selecting a result adds a normal history entry and highlights the setting. Clearing the query keeps the current pane, and Back/Forward follows normal history during search. Category names and descriptions also provide one entry that opens the top of the pane. Color controls on the same row share one result.
- Window opacity can be adjusted with a 0–100% slider or a numeric field. Invalid opacity input, including decimals, is rejected when editing finishes; typed and pasted text follow the same rule.
- Existing KeyEquivalents.plist entries for the former Key Bindings submenu’s first item still apply to the Key Bindings item in Source. Entries for removed editing items or out-of-range numbers are ignored. macOS App Shortcuts (NSUserKeyEquivalents) use exact menu titles: recreate an assignment whose title changed. The file editors are now buttons in Settings → Keyboard and cannot be assigned by their former menu titles.
- Settings has ten categories: General, Documents and Saving, Editor, Spell Checking, Appearance, Preview, Typesetting, Console, Keyboard, and Updates.
- Spell Checking offers “Use LaTeX-aware spell checking (recommended)” with “Edit LaTeX exclusion rules…” beneath it, or “Use legacy spell checking” with three indented options. “Check Spelling” is independent.
- Keyboard contains text input key bindings, Esc/Tab command completion, BibDesk completion and both file editors; these editors have moved from the Source menu. When Tab triggers completion it is reserved for completion. Key bindings and command completion appear above shortcut search. Each group has a heading and a rounded card. Searching for Tab when it triggers completion reveals and highlights that setting.
- General provides a link to Comment Lines and Hidden Settings.
- Find TeX and Ghostscript installations automatically. When TeXShop is first used, and with Auto Setup… under Settings → Typesetting, the installations found are listed with their versions. The newest is selected, and another can be chosen for TeX and for Ghostscript separately. The paths change only after confirmation; the TeX and Ghostscript paths are updated.
- Correct overlapping controls, clipped labels, and incorrect control connections throughout the localized Settings windows. Add missing bracket-color controls in Dutch.
- Choose the markers for spaces, full-width spaces, newlines and tabs from pop-up menus under Settings → Editor, with more choices for newlines and tabs.
- Show bracket and expl3 colors from the theme being edited, update inherited colors correctly, and preserve the theme when a color change is ignored. Older themes without bracket colors use the marker color.
- Settings has a compact sidebar, overview cards and named groups with switches and right-aligned controls. Settings Profile is in General.
- A note with a yellow warning symbol explains changes to the spell-checking method, new-PDF zoom or default encoding when relevant. Auto Save requires a restart. The standard Find Panel and Find Bar switch immediately; switching to or from OgreKit requires a restart.
- Theme colors are organized into eight named groups. A failed save restores the last saved colors.
- The zoom setting controls new PDFs. Source and console font settings apply to open and future windows.
- Apply settings profiles after showing their reset scope and TeX engine path. Reset known editing, engine, display, hidden settings, and the running Dock icon; preserve shortcuts, system language, window layouts, automatic updates, theme files, and unrecognized settings. Theme selections may change.
- Fix Make Default Editor for .tex files.
- Add an option under Settings → Editor to treat @ as part of command names in syntax coloring.
- Add an option under Settings → Editor to color expl3 code by default. Each document reads it when it opens, and the Source menu still turns expl3 coloring on or off for a single document.
- Standardize the Settings terminology, remove obsolete PDFSync choices and ineffective settings, and consistently use the modern toolbar icons.
