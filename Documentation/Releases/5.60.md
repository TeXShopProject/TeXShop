# TeXShop 5.60

<!-- release-status: draft -->

TeXShop 5.60 fixes typesetting cancellation and keeps the PDF preview position on macOS 27. It adds LaTeX-aware spell checking, pinnable and movable link previews, a redesigned Settings window with automatic detection of TeX and Ghostscript, Command-0 for the console, and a new app icon.

## Typesetting and stability

- **Critical fix:** Fix a problem where Stop reported that typesetting had been aborted but left TeX running. Starting another typesetting job now also stops the previous job and its child processes.
- Run Experiment jobs in a separate console with independent input, cancellation and cleanup, so they do not interfere with normal typesetting. Closing or replacing an Experiment cancels only its own job. The Experiment console floats with the Experiment source and preview panels: it comes in front of them when an Experiment is typeset and with Show Console (Command-0), and a panel that is clicked comes in front of it again. When Settings → Console shows the console only when an error occurs, the Experiment console stays hidden until TeX reports an error or waits for input. Reported by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#8](https://github.com/TeXShopProject/TeXShop/issues/8)).
- Find pictures and other files in Experiment typesetting as when the document is typeset, also with paths beginning with `./`, such as `\graphicspath{{./figures/}}`: the temporary folder of an Experiment holds copy-on-write clones of the items next to the document, so what the typesetting writes leaves the document’s folder alone. Resolve `\ref`, `\pageref` and `\cite` from the document’s last typesetting. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#8](https://github.com/TeXShopProject/TeXShop/issues/8)).
- After the first Experiment typesetting, show the top of the first page, where the output is, instead of the middle of the page. Later typesetting keeps the position being viewed. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#20](https://github.com/TeXShopProject/TeXShop/issues/20)).
- Show the source in the Experiment window like the document’s source: the same font, tabs, line spacing, wrapping, syntax colors, current line highlight, block cursor, invisible characters, line numbers and brace matching. Changing any of these from a menu or in Settings changes the Experiment window at once.
- Add tools to the Experiment preview’s toolbar: Scroll, Select Text, Magnify and Select PDF, as in the Preview window, and Zoom Out, Zoom In, Zoom to Content, which enlarges the typeset part of the page to fill the window, and Zoom to Content Width (see below). A rectangle drawn with Select PDF is copied in the format chosen in Copy Format. The Experiment preview remembers its tool separately from the Preview window.
- Make the bar below the Experiment source narrow, with a small Typeset button, to match the thin frames of the Experiment windows.
- Handle failures to launch typesetting tools and missing command-search paths more reliably, and avoid an indefinite wait when stopping helper processes.
- Show a sheet when a specified TeX root file cannot be found.
- Let console output be selected and copied while TeX runs or waits for input after an error. New output no longer replaces the selection, and the console does not scroll while text is selected. Moving the focus out of the input field no longer sends an empty line to TeX; Return still does. The Experiment console behaves the same.
- Return or Enter in the console output, for example after clicking it to read the log, answers TeX as Return in the empty input field does, and moves the focus back to the input field. Text typed in the input field is kept and not sent. Return with Shift, Option, Control or Command is not affected. The Experiment console behaves the same. Sending a line just after TeX quits no longer makes TeXShop quit.
- When a file with a `% !TEX root` line is typeset, Command-1 in the root document’s preview returns to that file. A typeset or Command-1 in the root document’s own window makes that window the destination again.
- Trash leftover `.synctex.gz(busy)` files, which an interrupted run leaves behind, with the other auxiliary files.
- Fix errors involving empty documents, isolated quotation marks, and save-completion handling.
- Improve the handling of console output and log files that contain mixed encodings or broken characters, including UTF-8 characters split by TeX’s line wrapping.

## LaTeX-aware spell checking

- Add LaTeX-aware spell checking, based on suggestions from [Ralph Martin](https://github.com/ralphrmartin). It checks prose while skipping TeX commands, comments, mathematics, and arguments used for references and similar purposes. The feature is enabled by default and can be turned off under Settings → Spell Checking.
- Recognize supported macro definitions and language-switching commands when identifying text to check. The spelling panel can check passages in the specified language.
- Add editable spelling-exclusion rules, a replacement field and Change All for words in the checked text, and a way to forget learned words found in the current document. A Change All operation can be undone in one step.
- Skip, with the default exclusion rules, the arguments that are not prose, such as keys, labels, lengths, colors and units, of the commands of common packages: amsmath, mathtools, graphicx, xcolor, tikz, geometry, fancyhdr, microtype, booktabs, tabularx, enumitem, hyperref, cleveref, biblatex, natbib and siunitx, together with the math environments of amsmath and mathtools. A command that the document defines itself keeps its own definition, the column specification of tabularx and tabulary is no longer checked, and skipped arguments may continue on the next line. Provided by [Ralph Martin](https://github.com/ralphrmartin).
- Fill the replacement field for Change All with the suggestion selected in the spelling panel, by clicking it or with the arrow keys. When there is only one suggestion, it is filled in as soon as the word is shown. The text changes only when Change All is used. Proposed by [Ralph Martin](https://github.com/ralphrmartin).
- Make Change in the spelling panel beep and do nothing, as Change All does, when other text has been selected or the document edited since the word was shown, instead of replacing that text. Proposed by [Ralph Martin](https://github.com/ralphrmartin).
- Improve Find Next, scrolling to misspelled words, and spell-checking performance in long documents and split editors.
- List the dictionaries under Settings → Spell Checking by each language’s own name, such as English (United States), English (United Kingdom) or Deutsch, instead of identifiers such as `en` and `en_GB`. A dictionary stored in an earlier form, such as `en_US` or `English`, is shown as chosen, and documents are checked in the language shown; a chosen dictionary that is no longer installed still appears under its name. Reported by [Herb Schulz](https://github.com/herbs) ([#32](https://github.com/TeXShopProject/TeXShop/issues/32)).
- Use the dictionary chosen under Settings → Spell Checking, or automatic language detection, in the open documents as soon as it is chosen, not only in documents opened later. When no document’s source window is in front, it is also used at launch, after a document is closed and when it is chosen, so the spelling panel shows it from the start. A document keeps the language of its `% !TEX spellcheck` line, or a language chosen for it in the spelling panel. Reported by [Herb Schulz](https://github.com/herbs) ([#32](https://github.com/TeXShopProject/TeXShop/issues/32)).
- Fix opening a file with a `% !TEX spellcheck` line changing the spelling language of the document that was in front.
- Show the misspelled word in the middle of the source window when the spelling panel is opened, or Find Next or Check Document Now is used, in a long document. In a high window the word could stay below the visible part of the source. Opening the spelling panel also keeps the word found, rather than the word found by the system’s own search, which does not skip commands; that search could replace it a moment later, for instance when the panel checks more than spelling. Reported by [Herb Schulz](https://github.com/herbs) ([#38](https://github.com/TeXShopProject/TeXShop/issues/38)).

## External file changes and PDF preview

- Use the recorded source-click position and the clicked split editor for SyncTeX, including clicks at the start of a line and context-menu actions. Match valid filesystem aliases to SyncTeX inputs, prefer an exact recorded path, and reject paths that cannot be resolved.
- Preserve the page-relative position in both PDF panes after reloading, including content insets on macOS Tahoe. Preserve it across single-page and two-page navigation on macOS 27 when native PDFKit moves the viewport. Reported by [svb-bit](https://github.com/svb-bit) ([#9](https://github.com/TeXShopProject/TeXShop/issues/9)).
- **Changed behavior:** In single-page and two-page layouts, when an enlarged page can scroll vertically, the Up and Down Arrow keys scroll within the page at a consistent on-screen step and stop at its edge instead of turning the page. Use Command-Right/Left Arrow, Page Up/Page Down, or Space to change pages. Suggested by [svb-bit](https://github.com/svb-bit) ([#9](https://github.com/TeXShopProject/TeXShop/issues/9)).
- On macOS 27, keep the horizontal position of an enlarged page in single-page and two-page layouts when Option or Command with the Up and Down Arrow keys, Space, Home, End or the page number field move to another page. A SyncTeX or Find result no longer moves the margins sideways either: the view scrolls sideways only when the result is out of view. Reported by [svb-bit](https://github.com/svb-bit) ([#9](https://github.com/TeXShopProject/TeXShop/issues/9)).
- Add “Do not turn pages by scrolling” under Settings, Preview, Display. In Single Page and Two Page display, scrolling past the top or bottom of a page with the mouse wheel or the trackpad moves to the previous or next page, as in Apple’s Preview; with this switch on, scrolling stops at the edge of the page. It takes the place of “Do not scroll” for the page buttons, which had no effect since TeXShop moved to PDFKit and is removed. Suggested by [svb-bit](https://github.com/svb-bit) ([#9](https://github.com/TeXShopProject/TeXShop/issues/9)).
- Remove the Apple Distiller choice under Settings, Typesetting. It called `/usr/bin/pstopdf`, which macOS 14 removed, so PostScript is now always converted with Ghostscript. The group is named Ghostscript, and its switch “-dALLOWPSTRANSPARENCY”.
- Remove “Smooth text and line art” under Settings, Preview, Display. It only chose how images in the PDF are interpolated; images are now always interpolated, and the hidden setting InterpolationValue still applies.
- Make the Home URL setting for the HTML window work, and open the TeXShop web site by default. The setting was never used, and any value kept the HTML window from opening; the window now opens the web address or file it names, or `https://texshop.app` when it is empty. The sample page it used to show is no longer bundled.
- Move Open Style File from the Help menu to the File menu, below Open, and find its files with `kpsewhich -progname=latex -format=tex` by default instead of the teTeX script kpsetool, which only called kpsewhich. Its panel is titled Open Style File and no longer suggests lower case, since names such as MnSymbol.sty must be typed as they are. The setting under Settings, Typesetting is now named kpsewhich; a command saved there keeps working.
- Move Use Color Mapping and Foreground Prominence into the Copy Images group under Settings, Preview, since they affect copied images only, and add short explanations to ten settings.
- Give the whole-number fields under Settings, Editor, Format arrow buttons and accept only digits in them, and explain the five settings of this group. The source window now uses the same ranges as these fields, so a value saved outside a range, for example with `defaults write`, applies as the nearest end of the range, and a fraction is dropped.
- Keep PDF link previews within the page, with surrounding text and the appropriate column visible even for destinations near an edge. In Single Page and Two Page display, a preview also stays within the window: a preview taller than the window becomes smaller, and one that does not fit on its side of the link appears on the other side. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#7](https://github.com/TeXShopProject/TeXShop/issues/7)).
- Pin an internal-link preview with Option, then move the pointer freely while explaining its contents; press Escape to dismiss it. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#10](https://github.com/TeXShopProject/TeXShop/issues/10)).
- Size internal-link previews to the text column of the target page, with a margin of about 5% of the column, so whole lines appear at the usual scale and a pinned preview has room to scroll; in two-column documents only the target column is shown. A window too narrow for a preview makes it smaller, but never below half size; in Single Page and Two Page display, a window too low for it can make it smaller still. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#12](https://github.com/TeXShopProject/TeXShop/issues/12)).
- Drag a pinned internal-link preview to move it, even mostly out of view, drag its edges or corners to resize it at the same text size, and scroll over it to see more of the linked page. With any tool but the hand, text in it can be selected and copied. A pinned preview stays until Escape; clicking inside or outside it with any tool, using another window, or splitting or unsplitting the Preview window no longer dismisses it. In the Multi-Page and Double Multi-Page display formats, a link preview always appears below the link, or above it with Shift, so it no longer covers the text next to the link; it keeps its size and only moves sideways to stay in view, even when part of it then lies outside the window. A preview starts just above the link target and shows what follows it. When the target is near the bottom of its page, the preview no longer fills up with material from above the target: in these continuous formats it goes on with the top of the next page, so a statement broken by a page break can be read in one preview, scrolled into in a pinned preview, and selected across both pages; in the other formats, and on the last page, the preview becomes lower. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#14](https://github.com/TeXShopProject/TeXShop/issues/14)).
- Keep parts of the linked page from showing around an internal-link preview while the Preview window scrolls. Reported by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#21](https://github.com/TeXShopProject/TeXShop/issues/21)).
- Keep the top of the Preview window where it is on the screen when the window is split or unsplit, at any magnification, and make Switch Views exchange exactly what the two views show, so that the views no longer creep. Unsplitting now keeps any scrolling of the top view instead of returning to the position before the split. Reported by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#23](https://github.com/TeXShopProject/TeXShop/issues/23)).
- Show the label of the linked page, such as “Page 157”, in the lower right corner of an internal-link preview, as Skim does. The label is the page number given in the PDF, which may differ from the page’s position in the file; a PDF without page labels shows that position. While link previews are on, PDFKit’s “Go to page” tool tip, which gave the page’s position in the file and could cover the text, no longer appears over internal links. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#17](https://github.com/TeXShopProject/TeXShop/issues/17)).
- Keep the chapters and sections opened in the outline of the Preview window’s drawer open when the document is typeset again, and keep the outline’s scroll position. Entries are matched by their titles, so entries that remain in the new outline stay open. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#19](https://github.com/TeXShopProject/TeXShop/issues/19)).
- When the Preview window is split into a top and a bottom part, dragging the divider keeps the text at the top of each part where it is: the top part shows more or less below it, and the text of the bottom part moves with the divider, like a sheet of paper laid over the lower part of a page. Changing the height of the window also keeps the text at the top of both parts. The two parts stay steady while the divider is dragged, and a part pushed out of sight at the top or the bottom of the window comes back with the same text at its top when the divider is dragged back. The top part is the one that stays when the window is unsplit. When the scroll bar is always shown in the system settings, a horizontal scroll bar that comes or goes in the Preview, because the width of a part or of the window or the magnification changes, now only covers the bottom of the Preview or shows it again, and the text no longer moves up or down. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#24](https://github.com/TeXShopProject/TeXShop/issues/24)).
- Switch Views now exchanges the two parts of a split Preview window completely. Each part keeps its size, so a divider that was dragged away from the middle moves to the other side, and each part takes along its place, display format, magnification, selection and pinned internal-link preview; the active part stays active. Switching again gives back the original arrangement. As before, the top (or left) part is the one that stays when the window is unsplit, so after switching it is the material of the other part that stays. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#25](https://github.com/TeXShopProject/TeXShop/issues/25)).
- In a split Preview window, the outline in the drawer follows the active part, also when that is the bottom (or right) part: as the part scrolls, the outline marks the chapter or section shown in it, and when the other part is clicked, the outline moves to the chapter or section shown in that part. The outline marks the entry that starts on the page shown; if there is no such entry, it marks the last entry that starts before it, rather than the next one. Reported by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#25](https://github.com/TeXShopProject/TeXShop/issues/25)).
- Add Zoom to Content Width: the typeset part of the page in view fills the width of the preview, and its top comes to the top of the preview, so the margins of the page and a page number or note at the bottom of the page no longer make the text small. Zoom to Content still makes the whole typeset part, including the page number, fit in the preview. Both are buttons in the toolbar of the Experiment preview, and the Preview window and the single window have them together as one item that can be added to the toolbar. In two-page layouts the pair of pages side by side count together, and turned pages are used as they are shown. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#33](https://github.com/TeXShopProject/TeXShop/issues/33)).
- In the Preview window, the contextual menu opened over an internal link with a Control-click or a right-click has a new item, “Split Window with Link”. It shows the linked place in the other part of a split window, splitting the window first if needed, side by side with Option, while the part with the link stays where it is. The other part keeps its magnification and display format, and Back takes it back. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#31](https://github.com/TeXShopProject/TeXShop/issues/31)).
- The Split Preview and Split Source buttons in the toolbar show a window split into a top and a bottom part. Hold Option with the pointer over one of them, and it shows the window split into a left and a right part, as an Option-click does. The tool tip of each button shows this as well. A shortcut set for Split Window Vertically now puts the parts of the Preview side by side also without Option, and in one localization, Split Window Vertically again takes the place of Split Window in the Window menu while Option is held. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#14](https://github.com/TeXShopProject/TeXShop/issues/14)).
- In a split Preview window, the active part, which the toolbar and the Preview menu work with, has a thin line along its edges, in the color chosen in System Settings, while the window is in front. Suggested by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#14](https://github.com/TeXShopProject/TeXShop/issues/14)).
- In the window that shows the source and the Preview side by side, remember where the divider was last dragged, as the share of the window given to the source, and open every such window with the divider there: for any document, at any window size, and when TeXShop restores such a window at launch. The source keeps its share when it is on the right. Suggested by [Felix Finster](https://github.com/felix-finster) ([#26](https://github.com/TeXShopProject/TeXShop/issues/26)).

## Editing and keyboard navigation

- Edit menu shortcuts in Settings → Keyboard. Search by Function finds command names; Search by Key records a key to show matching menu commands and macros, including inactive assignments. Show in Macro Editor selects the matching macro. A new shortcut is recorded by pressing it, shortcuts already in use are reported, and one or all shortcuts can be restored. Shortcuts set in `KeyEquivalents.plist` remain the defaults. For the same key and modifiers, menu commands take precedence over macros; macros can use keys freed by customization. Confirm before assigning a macro’s key to a menu command. The Macro Editor marks inactive shortcuts, identifies the conflicting command and key, and asks about new or changed conflicts when saving. The bundled New array macro now uses Control-Shift-Command-A.
- Improve opening, scrolling, and editing long source documents.
- Preserve explicit left alignment in right-to-left paragraphs.
- Use Command-0 to show the current document’s console. Press it again in the console to return to the source or PDF window that opened it; if there is no originating window, return to the source. This follows the existing Command-1 behavior. Suggested by [Nicolas Martignoni](https://github.com/martignoni) ([#2](https://github.com/TeXShopProject/TeXShop/issues/2)).
- Keep the Tags menu correctly localized when reopening a document in the combined source-and-preview window.
- Recolor text that a line break moves out of a comment line, so that it no longer keeps the comment color. Reported by [Uwe Schmock](https://github.com/Uwe-Schmock) ([#16](https://github.com/TeXShopProject/TeXShop/issues/16)).
- Add Character Type Conversion to the Edit menu and to the source window’s contextual menu. It converts the selection between hiragana and katakana, between fullwidth and halfwidth digits and letters, between Unicode characters and ajmacros commands or `\UTF`/`\CID` commands, and from curly quotes to TeX quotes. A character sequence becomes a `\CID` command only when it has an Adobe-Japan1 glyph; emoji and other sequences without one are left as they are. With nothing selected, it asks before converting the whole document. Each conversion can be undone.
- Add Unicode Normalization to the Edit menu and to the contextual menu. It offers NFC, NFD, NFKC and NFKD, and Modified NFC and Modified NFD, which keep CJK compatibility ideographs unchanged. Character Info then shows the normalized selection.
- Add Swap with Clipboard to the Edit menu. It replaces the selection with the text on the clipboard and puts the replaced text on the clipboard. To exchange two pieces of text, copy one, select the other and choose Swap with Clipboard, then paste where the first one was. With nothing selected, it pastes as usual.
- Expand `#PASTE#` in macros and key bindings to the text on the clipboard, as `#SEL#` stands for the selection.
- Show control characters other than tab, line feed and carriage return as U+FFFD in the invisible character color, whether or not invisible characters are shown. Before, they took no space, and a form feed hid the rest of the document.
- Color fullwidth letters, digits and symbols, and the minus sign, which look much like ASCII in Japanese text, with the new Fullwidth and Fullwidth (Background) colors under Settings → Themes → Highlights. The bundled themes define these colors; themes without them, including existing themes in `~/Library/TeXShop/Themes`, show these characters like other text.
- Leave text being composed with an input method, such as Japanese before it is committed, uncolored, and color the source once it is committed or canceled. Typing Japanese no longer slows down by recoloring the visible text at every keystroke, and a fullwidth digit being typed is no longer highlighted. The Experiment source behaves the same.
- Give each bundled theme expl3 colors that suit it. Themes without these colors, including existing themes in `~/Library/TeXShop/Themes`, keep the built-in expl3 colors.
- Click a line number to select that whole line, including its line ending, or drag over the line numbers to select several whole lines; the text scrolls when the pointer goes above or below it. Shift-click extends the selection to whole lines. The numbers of the lines selected this way are bold until the selection changes. This works in the source, the log and the Experiment source.

## Opening and saving documents

- Detect the encoding of a file that has no encoding magic comment when it is opened. Unicode files with or without a byte order mark, Japanese, Chinese and Korean files, and files in one-byte encodings of the user’s languages are recognized, with the encoding declared to inputenc as a hint. A hidden setting turns the detection off.
- Keep the byte order mark of UTF-8 files and the byte order of UTF-16 files when saving, and read encoding magic comments in UTF-16 files.
- Read GB 2312 files correctly, and stop a file that could not be read in its specified encoding from being damaged when it is saved.
- Always write TeX’s backslash and tilde as the bytes 0x5C and 0x7E in Japanese encodings. A typed backslash or tilde no longer becomes a full-width backslash or wave dash, or the byte 0x80, in Mac Japanese and Shift JIS X0213 files, and a yen sign typed for a backslash no longer becomes “?” in Windows Shift JIS, EUC-JP and ISO-2022-JP files.
- Use UTF-8 rather than Latin 9, with a message, when an encoding name is not recognized, and write project files in UTF-8.
- When an opened file has Windows (CRLF), classic Mac (CR) or mixed line endings, tell the user that they have been changed to LF. The notice can be turned off for each file.
- Fix the encoding menu in the Save dialog, which did not change the encoding of the saved file. The menu can now be shown from Settings → Documents and Saving. When the source has an encoding magic comment naming a known encoding, the menu shows that encoding and cannot be changed, unless the file could not be read in that encoding.
- Add settings under Settings → Documents and Saving to turn autosave and Versions on or off and, while autosave is off, to keep the previous file as `name~` when saving.
- Fix saving with Automatic UTF-8-Mac to UTF-8 Conversion, which wrote an empty file when the text consisted only of CJK compatibility ideographs.
- Fix saving with utf.sty export when a line break or tab is followed by a combining mark. The two were written as one `\CID` command for a glyph that does not exist, and the line break was lost; the mark is now written on its own.
- **Changed behavior:** Decode `\UTF`, `\UTFK`, `\UTFT` and `\UTFC` commands when a file is opened, also when utf.sty export is off. A decoded U+FF5E or U+FF0D becomes U+301C or U+2212, which Japanese encodings can save; characters typed in the file are left as they are. Only commands for characters outside JIS X 0208, which saving with utf.sty export writes, are decoded; commands for other characters, commands after an escaped backslash such as `\\UTF`, and surrogate code points are left as they are.
