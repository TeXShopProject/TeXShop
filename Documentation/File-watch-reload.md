# 外部ツールによる書き込み中のファイルの再読み込み

## 原因

TeXShopは開いている.texファイルをdispatch sourceで監視し、外部ツールが書き込むとrevertToContentsOfURL:で再読み込みする（TSDocument.mのwatchFile:）。

1. 書き込みイベント（DISPATCH_VNODE_WRITE）を受けた時点で、待たずに再読み込みしていた。外部ツールが何回かに分けて書き込むと、書き込みの途中までを読んでエディタに表示する。20480バイトずつ書くツールでは、エディタが先頭の20480バイト付近で切れた状態になる。
2. revertToContentsOfURL:は、監視を解除し、ファイルを読み、読んだ後で監視を再登録する（readFromURL:内のwatchFile:）。読み終えてから再登録するまでの間に終わった書き込みはイベントとして届かない。その場合、次に外部から書き込まれるまで、エディタは途中までの内容のままになる。

## 修正

- WRITEイベントは0.1秒待ってから再読み込みする。書き込みが続く間はイベントのたびに待ち直す。
- readFromURL:でファイルを読む前に、サイズと更新日時を記録する。再読み込みの完了時に現在の値と比べ、違っていれば（読んでいる間にファイルが変わった）もう一度再読み込みする。
- open()が失敗したときは、無効なファイル記述子を監視しない。

DELETE・REVOKEの処理、未保存の変更がある場合に監視を止める動作、保存時の処理は変更しない。

## 検証

Tests/external-writer.pyは、開いている.texファイルを20480バイトずつ書き換える。1ラウンドは、先頭の40バイト、20480バイトのブロックをチャンク数だけ、末尾の15バイトの順に書き、各ブロックの間に指定した時間（ミリ秒）だけ待つ。

検証にはmacOS 15.5でDebugビルドを使った。ad-hoc署名のためHardened Runtimeを無効にし、watchFile:、readFromURL:、revertToContentsOfURL:にNSLogを加えて、再読み込みごとにエディタの文字数とディスク上のサイズを記録した。エディタ上の目視確認ではなく、記録した文字数とディスク上のサイズを比べている。

- 修正前（5チャンク、5ミリ秒間隔）: 130ラウンド中3回、最後の再読み込みの後もエディタの文字数がディスク上のサイズより少ないまま残った。うち1回は、再読み込みで102440バイトを読んだ後、末尾の15バイトが再登録の前に書かれ、イベントが届かなかった。1ラウンドの再読み込みは1〜3回で、98ラウンドでは最初の再読み込みが20520文字（40 + 20480）で止まっていた。
- 修正後（5チャンク、5ミリ秒間隔）: 150ラウンドで0回。1ラウンドに再読み込みは1回だった。
- 修正後の追加条件: 5チャンク・0ミリ秒間隔を30ラウンド、5チャンク・1ミリ秒間隔を60ラウンド、8チャンク・150ミリ秒間隔を5ラウンド、40チャンク・2ミリ秒間隔を20ラウンド。いずれも0回。

データの量は少なく、再現はタイミングに依存する。TeXShop本体のGUIで外部ツールと組み合わせた通し操作は、確認していない。
