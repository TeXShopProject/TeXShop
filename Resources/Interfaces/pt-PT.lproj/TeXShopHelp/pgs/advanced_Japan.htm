Composição em japonês

O TeX Live inclui os motores TeX japoneses pTeX e upTeX, com o pLaTeX e o upLaTeX, bem como o LuaLaTeX com o pacote LuaTeX-ja. A ajuda japonesa do TeXShop descreve a composição em japonês com mais pormenor.

Perfis do motor para japonês

A forma mais rápida de configurar o TeXShop para documentos em japonês é um perfil do motor. Em Definições › Composição › «Perfil do motor», escolha um dos três perfis japoneses:

PerfilComposiçãoBibTeX, índice, MetaPost
upLaTeX + dvipdfmxuplatex e depois dvipdfmxupbibtex, upmendex, upmpost
pLaTeX + dvipdfmxplatex e depois dvipdfmxpbibtex, mendex, pmpost
LuaLaTeX (japonês)lualatexupbibtex, upmendex, mpost

Os perfis japoneses definem também UTF-8 como codificação dos novos documentos, definem o dicionário ortográfico como deteção automática do idioma e ativam «Converter automaticamente UTF-8-MAC para UTF-8». O pLaTeX + dvipdfmx ativa também «Converter para \UTF / \CID do pacote otf», e todos os outros perfis desativam-na. Uma folha enumera os valores que o perfil define antes de confirmar.

Caracteres fora do JIS X 0208 com o pLaTeX

O pTeX lê código-fonte em UTF-8, mas internamente só conhece os caracteres do JIS X 0208, pelo que os outros caracteres, como 鷗 em 森鷗外, se perdem. O pacote otf imprime-os com comandos como \UTF{9DD7}. A definição «Converter para \UTF / \CID do pacote otf», no grupo «pLaTeX japonês» de Definições › Composição, permite escrever estes caracteres tal como são:

  • Quando o documento é guardado, cada carácter fora do JIS X 0208 é escrito como \UTF{XXXX}, e uma variante de glifo escolhida no editor como \CID{number}. Se um destes comandos terminar uma linha, é acrescentado % a seguir, para que não apareça nenhum espaço no resultado.
  • Quando um documento é aberto, estes comandos são convertidos de novo nos caracteres, quer a definição esteja ativa quer não, pelo que a janela do código-fonte mostra sempre os próprios caracteres.

O documento precisa de \usepackage{otf}. Por exemplo, a janela do código-fonte mostra

\documentclass{jsarticle}
\usepackage{otf}
\begin{document}
森鷗外 was a famous novelist in Japan.
\end{document}

enquanto o ficheiro contém 森\UTF{9DD7}外. O upLaTeX e o LuaLaTeX tratam o Unicode diretamente e não precisam de conversão.

Para converter manualmente parte de um texto, selecione-a e use Edição › Conversão do tipo de carácter › Caracteres Unicode → \UTF / \CID ou \UTF / \CID → Caracteres Unicode. O mesmo submenu converte entre hiragana e katakana, entre dígitos e letras de largura total e de meia largura, entre caracteres como os números em círculo e os comandos do pacote ajmacros, e converte aspas tipográficas em aspas do TeX. Sem nada selecionado, o TeXShop pergunta se deve converter o documento inteiro; todas as conversões podem ser anuladas.

Caracteres compostos e decompostos

Alguns caracteres japoneses têm duas formas Unicode. が pode ser um único carácter (U+304C) ou か (U+304B) seguido do sinal combinatório de som sonoro (U+3099). Ambos têm o mesmo aspeto, mas o TeX trata-os como diferentes, pelo que um comando definido com uma forma não é encontrado quando é usado com a outra:

\def\が{GA}
\が   % Undefined control sequence if this が is decomposed

O texto decomposto vem muitas vezes de nomes de ficheiros, que os discos HFS+ guardam em forma decomposta; esta forma chama-se UTF-8-MAC. Quando Definições › Documentos e gravação › «Guardar documentos» › «Converter automaticamente UTF-8-MAC para UTF-8» está ativo, o TeXShop combina esses caracteres em caracteres únicos ao guardar um documento. Deixa inalterados os ideogramas de compatibilidade CJK e outros caracteres que a composição padrão (NFC) substituiria por caracteres diferentes; esta forma chama-se NFC modificada.

O submenu Edição › Normalização Unicode converte uma seleção, ou o documento inteiro, para NFC, NFC modificado, NFD, NFD modificado, NFKC ou NFKD e, em seguida, mostra o painel «Informação do carácter» para o resultado, uma vez que o texto normalizado costuma ter o mesmo aspeto que antes.

O símbolo do iene e a barra invertida

Nos teclados japoneses, a tecla que ocupa o lugar da barra invertida escreve o símbolo do iene ¥, ao passo que os comandos do TeX começam pela barra invertida \.

  • Com o UTF-8, a codificação que os perfis japoneses definem, ¥ e \ são caracteres diferentes e ambos são mantidos. Ative Código-fonte › Associações de teclas para o documento: a lista de associações de teclas fornecida com o TeXShop transforma um ¥ escrito em \ e, como a sua coluna «Colar» está assinalada, também o ¥ do texto colado no código-fonte. Consulte Associações de teclas.
  • Quando a codificação dos novos documentos é uma das codificações japonesas, o TeXShop converte entre ¥ e \ à medida que escreve e cola. Com Japonês (Mac OS, ShiftJIS ¥) e Japonês (Shift JIS X0213), a janela do código-fonte mostra o carácter de comando do TeX como ¥; com as outras codificações japonesas, mostra \.
  • Quando um ficheiro é guardado numa codificação japonesa, a barra invertida e o til são sempre escritos como os bytes 0x5C e 0x7E, que o TeX espera.

Outras definições para japonês

  • Definições › Editor › «Caracteres invisíveis» › «Espaço japonês» mostra o espaço de largura total quando os caracteres invisíveis são mostrados.
  • Definições › Editor › «Destaque de sintaxe» › «Destacar letras e símbolos de largura total» assinala as letras, os dígitos e os símbolos de largura total, que se confundem facilmente com os equivalentes ASCII, com as cores «Largura total» do tema.
  • Definições › Pré-visualização › «Direção das páginas» mostra as páginas da direita para a esquerda, como é necessário para texto vertical. As linhas % !TEX PageDirectionR2L e % !TEX PageDirectionL2R definem a direção para um único documento.

A conversão para \UTF / \CID e a normalização Unicode são explicadas em pormenor nos diapositivos de Yusuke Terada para o TUG 2013, https://tug.org/tug2013/slides/Terada-TeXShop.pdf.
