Composición en japonés

TeX Live incluye los motores TeX japoneses pTeX y upTeX, con pLaTeX y upLaTeX, así como LuaLaTeX con el paquete LuaTeX-ja. La ayuda en japonés de TeXShop describe la composición en japonés con más detalle.

Perfiles del motor para japonés

La forma más rápida de preparar TeXShop para documentos en japonés es un perfil del motor. En Ajustes › Composición › Perfil del motor, elija uno de los tres perfiles japoneses:

PerfilComposiciónBibTeX, índice, MetaPost
upLaTeX + dvipdfmxuplatex y luego dvipdfmxupbibtex, upmendex, upmpost
pLaTeX + dvipdfmxplatex y luego dvipdfmxpbibtex, mendex, pmpost
LuaLaTeX (japonés)lualatexupbibtex, upmendex, mpost

Los perfiles japoneses también establecen UTF-8 como codificación de los documentos nuevos, ajustan el diccionario ortográfico a la detección automática del idioma y activan «Convertir automáticamente UTF-8-MAC a UTF-8». pLaTeX + dvipdfmx activa además «Convertir a \UTF / \CID del paquete otf», y todos los demás perfiles lo desactivan. Antes de confirmar, una hoja muestra los valores que establece el perfil.

Caracteres fuera de JIS X 0208 con pLaTeX

pTeX lee código fuente en UTF-8, pero internamente solo conoce los caracteres de JIS X 0208, de modo que los demás caracteres, como 鷗 en 森鷗外, se pierden. El paquete otf los imprime con comandos como \UTF{9DD7}. El ajuste «Convertir a \UTF / \CID del paquete otf» del grupo «pLaTeX japonés» de Ajustes › Composición permite escribir estos caracteres tal cual:

  • Al guardar el documento, cada carácter fuera de JIS X 0208 se escribe como \UTF{XXXX}, y una variante de glifo elegida en el editor como \CID{número}. Si uno de estos comandos termina una línea, se añade % detrás para que no aparezca un espacio en el resultado.
  • Al abrir un documento, estos comandos se convierten de nuevo en los caracteres, tanto si el ajuste está activado como si no, de modo que la ventana de código muestra siempre los propios caracteres.

El documento necesita \usepackage{otf}. Por ejemplo, la ventana de código muestra

\documentclass{jsarticle}
\usepackage{otf}
\begin{document}
森鷗外 was a famous novelist in Japan.
\end{document}

mientras que el archivo contiene 森\UTF{9DD7}外. upLaTeX y LuaLaTeX manejan Unicode directamente y no necesitan ninguna conversión.

Para convertir a mano una parte del texto, selecciónela y use Edición › Conversión de tipo de carácter › Caracteres Unicode → \UTF / \CID, o \UTF / \CID → Caracteres Unicode. El mismo submenú convierte entre hiragana y katakana, entre dígitos y letras de ancho completo y de medio ancho, entre caracteres como los números en círculo y los comandos del paquete ajmacros, y las comillas tipográficas en comillas de TeX. Si no hay nada seleccionado, TeXShop pregunta si debe convertir todo el documento; todas las conversiones se pueden deshacer.

Caracteres compuestos y descompuestos

Algunos caracteres japoneses tienen dos formas en Unicode. が puede ser un único carácter (U+304C), o か (U+304B) seguido de la marca combinable de sonoridad (U+3099). Ambas formas se ven igual, pero TeX las trata como distintas, de modo que un comando definido con una forma no se encuentra cuando se usa con la otra:

\def\が{GA}
\が   % Undefined control sequence if this が is decomposed

El texto descompuesto suele proceder de nombres de archivo, que los discos HFS+ almacenan en forma descompuesta; esta forma se llama UTF-8-MAC. Cuando Ajustes › Documentos y guardado › Guardar documentos › «Convertir automáticamente UTF-8-MAC a UTF-8» está activado, TeXShop combina estos caracteres en caracteres únicos al guardar un documento. Deja sin cambios los ideogramas de compatibilidad CJK y otros caracteres que la composición estándar (NFC) sustituiría por caracteres distintos; esta forma se llama NFC modificado.

El submenú Edición › Normalización Unicode convierte una selección, o todo el documento, a NFC, NFC modificado, NFD, NFD modificado, NFKC o NFKD, y después muestra el panel «Información de caracteres» con el resultado, ya que el texto normalizado suele verse igual que antes.

El signo del yen y la barra invertida

En los teclados japoneses, la tecla situada en el lugar de la barra invertida escribe el signo del yen ¥, mientras que los comandos de TeX empiezan con la barra invertida \.

  • Con UTF-8, la codificación que establecen los perfiles japoneses, ¥ y \ son caracteres distintos y ambos se conservan. Active Código › Combinaciones de teclas para el documento: la lista de combinaciones de teclas que incluye TeXShop convierte un ¥ escrito en \ y, como su columna «Pegar» está marcada, también el ¥ del texto pegado en el archivo fuente. Consulte Combinaciones de teclas.
  • Cuando la codificación de los documentos nuevos es una de las codificaciones japonesas, TeXShop convierte entre ¥ y \ al escribir y al pegar. Con Japonés (Mac OS, ShiftJIS ¥) y Japonés (Shift JIS X0213), la ventana de código muestra el carácter de comando de TeX como ¥; con las demás codificaciones japonesas, lo muestra como \.
  • Al guardar un archivo en una codificación japonesa, la barra invertida y la tilde se escriben siempre como los bytes 0x5C y 0x7E, que es lo que TeX espera.

Otros ajustes para el japonés

  • Ajustes › Editor › Invisible › Espacio japonés muestra el espacio de ancho completo cuando se muestran los caracteres invisibles.
  • Ajustes › Editor › Resaltado de sintaxis › Resaltar letras y símbolos de ancho completo marca con los colores «Ancho completo» del tema las letras, dígitos y símbolos de ancho completo, que se confunden fácilmente con sus equivalentes ASCII.
  • Ajustes › Vista previa › Dirección de las páginas muestra las páginas de derecha a izquierda, como se necesita para el texto vertical. Las líneas % !TEX PageDirectionR2L y % !TEX PageDirectionL2R establecen la dirección para un documento.

La conversión a \UTF / \CID y la normalización Unicode se explican en detalle en las diapositivas de Yusuke Terada para TUG 2013, https://tug.org/tug2013/slides/Terada-TeXShop.pdf.
