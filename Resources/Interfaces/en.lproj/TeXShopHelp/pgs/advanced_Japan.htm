Typesetting in Japanese

TeX Live includes the Japanese TeX engines pTeX and upTeX, with pLaTeX and upLaTeX, as well as LuaLaTeX with the LuaTeX-ja package. The Japanese help of TeXShop describes Japanese typesetting in more detail.

Engine profiles for Japanese

The quickest way to set up TeXShop for Japanese documents is an engine profile. In Settings › Typesetting › Engine Profile, choose one of the three Japanese profiles:

ProfileTypesettingBibTeX, index, MetaPost
upLaTeX + dvipdfmxuplatex, then dvipdfmxupbibtex, upmendex, upmpost
pLaTeX + dvipdfmxplatex, then dvipdfmxpbibtex, mendex, pmpost
LuaLaTeX (Japanese)lualatexupbibtex, upmendex, mpost

The Japanese profiles also set UTF-8 as the encoding for new documents, set the spelling dictionary to automatic language detection, and turn on “Automatically convert UTF-8-MAC to UTF-8”. pLaTeX + dvipdfmx also turns on “Convert to otf Package \UTF / \CID”, and every other profile turns it off. A sheet lists the values the profile sets before you confirm.

Characters outside JIS X 0208 with pLaTeX

pTeX reads UTF-8 source, but internally it knows only the characters of JIS X 0208, so other characters, such as 鷗 in 森鷗外, are lost. The otf package prints them with commands like \UTF{9DD7}. The setting “Convert to otf Package \UTF / \CID” in the group “Japanese pLaTeX” of Settings › Typesetting lets you type these characters as they are:

  • When the document is saved, every character outside JIS X 0208 is written as \UTF{XXXX}, and a glyph variant chosen in the editor as \CID{number}. If such a command ends a line, % is added after it so that no space appears in the output.
  • When a document is opened, these commands are turned back into the characters, whether the setting is on or off, so the source window always shows the characters themselves.

The document needs \usepackage{otf}. For example, the source window shows

\documentclass{jsarticle}
\usepackage{otf}
\begin{document}
森鷗外 was a famous novelist in Japan.
\end{document}

while the file contains 森\UTF{9DD7}外. upLaTeX and LuaLaTeX handle Unicode directly and need no conversion.

To convert part of a text by hand, select it and use Edit › Character Type Conversion › Unicode Characters → \UTF / \CID, or \UTF / \CID → Unicode Characters. The same submenu converts between hiragana and katakana, between fullwidth and halfwidth digits and letters, between characters such as circled numbers and the commands of the ajmacros package, and curly quotation marks to TeX quotes. With nothing selected, TeXShop asks whether to convert the whole document; every conversion can be undone.

Composed and decomposed characters

Some Japanese characters have two Unicode forms. が can be a single character (U+304C), or か (U+304B) followed by the combining voiced sound mark (U+3099). Both look the same, but TeX treats them as different, so a command defined with one form is not found when it is used with the other:

\def\が{GA}
\が   % Undefined control sequence if this が is decomposed

Decomposed text often comes from file names, which HFS+ disks store in decomposed form; this form is called UTF-8-MAC. When Settings › Documents and Saving › Saving Documents › “Automatically convert UTF-8-MAC to UTF-8” is on, TeXShop combines such characters into single characters when it saves a document. It leaves the CJK compatibility ideographs and other characters that the standard composition (NFC) would replace by different characters unchanged; this form is called Modified NFC.

The submenu Edit › Unicode Normalization converts a selection, or the whole document, to NFC, Modified NFC, NFD, Modified NFD, NFKC or NFKD, and then shows the Character Info panel for the result, since normalized text usually looks the same as before.

The yen sign and the backslash

On Japanese keyboards the key at the place of the backslash types the yen sign ¥, while TeX commands begin with the backslash \.

  • With UTF-8, the encoding the Japanese profiles set, ¥ and \ are different characters and both are kept. Turn on Source › Key Bindings for the document: the key binding list that comes with TeXShop turns a typed ¥ into \, and, because its Paste column is checked, also the ¥ in text pasted into the source. See Key Bindings.
  • When the encoding for new documents is one of the Japanese encodings, TeXShop converts between ¥ and \ as you type and paste. With Japanese (Mac OS, ShiftJIS ¥) and Japanese (Shift JIS X0213), the source window shows the TeX command character as ¥; with the other Japanese encodings it shows \.
  • When a file is saved in a Japanese encoding, the backslash and the tilde are always written as the bytes 0x5C and 0x7E, which TeX expects.

Other settings for Japanese

  • Settings › Editor › Invisible › Japanese Space shows the fullwidth space when invisible characters are shown.
  • Settings › Editor › Syntax Highlighting › Highlight Fullwidth Letters and Symbols marks fullwidth letters, digits and symbols, which are easily mistaken for their ASCII counterparts, with the Fullwidth colors of the theme.
  • Settings › Preview › Page direction shows pages from right to left, as needed for vertical text. The lines % !TEX PageDirectionR2L and % !TEX PageDirectionL2R set the direction for one document.

The conversion to \UTF / \CID and Unicode normalization are explained in detail in Yusuke Terada’s TUG 2013 slides, https://tug.org/tug2013/slides/Terada-TeXShop.pdf.
