A document split into chapter files can be searched, and replaced in, in all its files at once. With one of its files in front, choose Find in TeX Sources with the Same TEX root… in the Find submenu of the Edit menu; when the file in front is the root file itself, the item is Find in TeX Sources with This File as TEX root…. The same item is in the menu of Find All in the Advanced Find Panel, and Apply to TeX Sources with the Same TEX root… in the menu of Replace All in the Multiple Replace window opens the window with the set chosen there. The items are dimmed for an untitled document and for a file whose name does not end in .tex.

The window Find in TeX Sources searches the root file and the .tex files in its folder and in the folders below it that name it with % !TEX root (or %!TEX root) in their first 20 lines; with the hidden setting UseOldHeadingCommands, also those that name it with %SourceDoc. The line under the modes says which root is searched, and the ? button at its end shows this rule. Files named in \input or \include are not followed, and the root file of a .texshop project is not used. Symbolic links to files are skipped, folders reached through symbolic links or aliases are not entered, and the folder TeXShop Backups is left out. The tree on the left lists the files; a file or a folder turned off there is not searched. The button Files not read at the bottom lists the files and folders that could not be read, with the reason.

Find lists every match with its line number. Replace shows each line before and after the replacement, and every match has a check box: a match turned off is not replaced. Multiple Replace applies a set of the Multiple Replace window, and lists the groups of changed lines, which are turned on and off as a whole; Edit… opens the set in that window. The find and replace fields and the options are those of the Advanced Find Panel. The list follows every change shortly after it, and the ↻ button (command-R) collects the files again. Clicking a row shows the match in its document; double-clicking brings that window to the front. The stop button, the Escape key or command-period stop a long search.

An open document is searched in the text on screen, with its unsaved changes. A file that is not open is read in the encoding TeXShop would open it with. A file that would not be written back exactly in that encoding, a file that has another name (a hard link), a file that cannot be written, and an open document that cannot be edited are only searched: they are marked ⊘, and the mark gives the reason.

Replace All asks before it replaces. The files are collected again and compared with the list before and after that question: if a file has changed or another file has appeared, nothing is replaced and the list is made again. With Save backups on, every file that is to be replaced in is first copied, as it was when the question was answered, into TeXShop Backups/<date and time> in the folder of the root file, under its path; an open document is copied in its text on screen. Then the files that are not open are written directly, in their own encoding, keeping their line endings, byte order mark, permissions and other attributes; this cannot be undone. The open documents are replaced on screen and are not saved: one Undo takes back the replacements of a document. Meanwhile the documents cannot be edited, saved, closed or typeset, and the stop button, Escape or command-period stop Replace All: the files already written and the open documents already done stay replaced, what was already put in the open document being replaced is taken back, and the rest is not replaced. Afterwards the files are searched again, the matches that were turned off stay off, and the line at the bottom says how many were replaced. When some files were not replaced, a sheet lists them with the reason, and Show in Finder opens the folder of the backup.

Right before a file is replaced, its content is compared with the version in the list, and the file is replaced at once. An application that writes the file in that brief moment without coordinating with other applications (through NSFileCoordinator) can still lose what it wrote; the backup keeps the version that was compared. Do not run Replace All while another program keeps writing the files.
