Settings has ten categories: General, Documents and Saving, Editor, Spell Checking, Appearance, Preview, Typesetting, Console, Keyboard, Updates. In Spell Checking, choose “Use LaTeX-aware spell checking (recommended)” with “Edit LaTeX exclusion rules…”, or “Use legacy spell checking” with three indented options. Changing the method preserves all child values. “Check Spelling” is independent. Keyboard places key bindings and command completion above shortcut search and the scrolling list. On a short window the input groups can be expanded one at a time. Searching for Tab when it triggers completion shows a reservation message and reveals the completion trigger. General links to Comment Lines and Hidden Settings. Disabled controls retain their saved values; an obsolete remembered category opens General.

Choose Settings and select Keyboard. Search by Function finds command names and menu paths. Search by Key records a key and lists matching menu commands and macros, marking assignment priority rather than whether the command can run in the current document. Searching changes no assignments and executes no commands, even for Command-Q or Command-W. System-reserved keys cannot be detected. Plain Escape, clicking the mode control again, changing categories, switching windows, or closing Settings ends recording. Macro rows are read-only. Show in Macro Editor selects the macro while preserving unsaved edits; if edits make its identity ambiguous, the current selection remains.

Choose Settings and select Keyboard to edit menu shortcuts. Select a command and press "Change…" (or double-click it), then press the new shortcut and choose "Apply"; press Escape to cancel. A shortcut must use the Command or Control key, or be a function key F1–F20. If the shortcut is already used by another command, TeXShop says so and does not change it. "Remove Shortcut", "Restore Default", and "Restore All…" remove or restore shortcuts. Changes take effect immediately and are kept when TeXShop restarts.

If another menu command uses the default shortcut, Restore Default refuses to restore it; change the other command first.

For the same key and modifiers, menu commands take precedence over macros, using their customized shortcuts when present. Macros can use keys freed by customization. Assigning or restoring a menu shortcut used by a macro asks for confirmation; the macro remains available in the menu, but its shortcut becomes inactive without changing its file. The Macro Editor marks inactive shortcuts and shows the conflicting command and key. Saving asks only about newly assigned or changed conflicting keys, including imported macros. You can return to editing, save with those keys inactive, or remove the conflicting keys and save. Existing unchanged conflicts do not interrupt saving. Among macros, the first occurrence of a key takes precedence. “Shortcut Unavailable” applies only to conflicts between menu commands. In the Preview window, Command-F and Command-G follow Find and Find Next, including custom assignments and removal.

Shortcuts set in KeyEquivalents.plist, described below, remain the defaults, and "Restore All…" does not change that file. Shortcuts for macros are set in the Macro Editor, and key bindings that insert text are set in the Key Bindings editor.

The keyboard menu shortcuts for TeXShop can be redefined. To do this, read the comments at the top of the file "KeyEquivalents.plist" and make appropriate changes. To do so, edit the file

~/Library/TeXShop/Menus/KeyEquivalents.plist
with TeXShop. Be sure to edit and save in UTF-8 format if you use Unicode characters.

Clicking a result row keeps key recording active. Only the result list scrolls vertically. Inactive results identify the winning assignment and key; macro paths use separators between groups.

Search Settings

Use Search Settings above the sidebar to find categories, labels, options and menu commands. Words separated by spaces must all occur in the same category. Case, Latin accents, fullwidth characters and hiragana/katakana variants are matched. Select a result to reveal and highlight its controls without changing their values. Clearing the query returns to the category used before searching. A menu-command match opens Keyboard and fills its Search by Function field. Search by Key keeps priority while recording. Personal paths, entered values and user-created theme names are not searched.
