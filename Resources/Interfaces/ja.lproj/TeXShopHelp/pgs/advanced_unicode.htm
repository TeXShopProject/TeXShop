Unicodeは世界の主要な言語（アラビア語、中国語、ギリシア語、ヘブライ語、日本語、ローマ字、ロシア語、その他の多くの言語）の文字を、単一の文字コード体系で処理する仕組みです。Cocoaのテキスト処理はUnicodeがベースになっているので、TeXShopでもそのままUnicodeを扱うことができます。Unicodeが実際にどんな感じなのか試してみるには、「システム環境設定」から「言語環境」を開き、「入力メニュー」タブで、すでに「入」になっているものに加えて別の言語を選んでみてください。たとえば、ギリシア語（よく知られていますね）、ヘブライ語（右から左へ書きます）、アラビア語（右から左へ書くうえ、リガチャ〔合字〕を広範に使用するので語末と語中とでは字体が異なります）、あるいは中国語などを選んでみるとわかりやすいでしょう。追加した入力メニューは、現在の入力言語を示す国旗で表示されます。

数文字打ち込んでみてから、他の言語に変え、さらにまた打ち込んでみます。

Unicodeファイルにはいくつかの形式があります。設定項目ではそのうちの２つを選べます。標準的なOS X UnicodeはMac OS Xではよく使われますが、これがTeXの世界で有用なのかどうかについてはわかりません。UTF-8 Unicodeは、普通のASCIIキャラクターが普通に表示されるので人気の高い方式です。UTF-8形式でファイルを保存すればTeXで処理することができますが、Unicode文字は疑問符に置き換えられてしまいます。

UTF-8 Unicodeで入力されたファイルを扱えるTeXパッケージもあります ； 下記を参照してください──

http://www.ctan.org/tex-archive/macros/latex/contrib/supported/unicode/

「otfパッケージ対応」について

pTeXはJIS X 0208にない文字（たとえば「鷗」）をそのままでは扱えません。otfパッケージを使うと、そうした文字を \UTF{9DD7} のようにUnicodeの番号で、異体字などを \CID{番号} のようにグリフ番号で書けます。

設定ウインドウの「タイプセット」カテゴリにある「pTeXサポート（日本用）」の「otfパッケージ対応」をオンにすると、TeXShopは書類を保存するときに、JIS X 0208にない文字をこの形式に置き換えます。書類を開くときには、この設定にかかわらず \UTF{…} を元の文字に戻します。戻すのは、保存のときに書き出すJIS X 0208にない文字のコマンドだけで、\\UTF{9DD7} のようにエスケープしたバックスラッシュの後のものはそのまま残します。

この機能の利点は、TeXShop内蔵のエディタで「鷗」や「閒」といった文字を直に入力できる、ということです。言い換えれば、コード表を調べたうえで本文中に \UTF{9DD7} や \UTF{9592}（ないしは \CID{07646} や \CID{08685} ）などと書く手間が省けるということです。

置き換えの規則は次のとおりです。

  • JIS X 0208にない文字は \UTF{16進数} になります。
  • エディタで選んだ異体字と、基本多言語面（BMP）の外の文字は、ヒラギノで描いたときのAdobe-Japan1のCIDを使って \CID{番号} になります。異体字は、ヒラギノに登録されているものだけを使います。登録されていない異体字の指定は保存できないので、元の字だけを書きます。ヒラギノで一つのグリフにならない文字は、エディタのフォントのグリフ番号を使います。これがCIDと一致するのは、ヒラギノなどのAdobe-Japan1のフォントだけです。
  • 置き換えた文字が行末に来たときは、余分な空白が入らないよう直後に「%」を付けます。
  • U+2015（HORIZONTAL BAR）は、pTeXが読めるU+2014（EM DASH）にします。

利用するにあたっては、プリアンブル部に、

\usepackage{otf}
と記述します。otfパッケージはTeX Liveに含まれています。（TeXShop 1.35で対応したutfパッケージ（\usepackage{utf}）も同じ形式を使いますが、現在はotfパッケージを使うのが一般的です。）

otfパッケージについてのさらに詳しい情報は、以下をご覧ください。

https://ctan.org/pkg/japanese-otf

【補足】
  • 「otfパッケージ対応」は、書類のエンコーディングにかかわらず働きます。ただし、SJISX0213の書類をpTeXで処理するには、これに対応したpTeXが必要です。
